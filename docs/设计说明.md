# 设计说明

## 一次通话的流程

1. **开场问**（仅部分概念有）：导师问一个与日常相关的问题，听完回应一句，不评判对错。
2. **讲解**：导师按提纲讲 2–3 分钟，遇到用户可能没学过的术语先用一句话解释。讲师提示词由概念 JSON 自动拼接，不看评分标准。
3. **复述**：导师说"轮到你了"，用户用自己的话讲。复述提示默认折叠，打开后会被记录。
4. **追问**：导师从三档追问中选一个问一次，难度按复述情况选择。
5. **结束**：导师简短收尾，不打分。转写保存后交给评分模型。

## 评分

- 评分模型只看**学员说的话**。导师的讲解、提示、纠正和追问措辞都不计分。
- 四个要点各打 0、1、2 分，每一分都要引用学员的原话作为证据，没有证据即 0 分。
- 只复述导师原话的，每个要点最多 1 分；列举类要点要 2 分，需要理由或讲解里没出现过的例子。
- 追问阶段补出的要点，最高补到 1 分，并计入总分。
- 转写明显错乱时不硬打分，标记 `asr_noisy` 和 `needs_review`，供重评或人工复核。
- 约束规则在 `public/scoring.js` 中，并有对应的离线测试。

## Key 与中转

- 两把 Key 只存在用户自己的浏览器里（`localStorage`）。
- 豆包实时语音的鉴权头 `X-Api-Key` 由 Worker 设置，浏览器不直连豆包。
- 方舟评分请求由 Worker 以 `Bearer` 方式转发。
- Worker 对评分请求体设置了大小上限（100 KB），并校验请求格式。

## 数据

- 100 个概念，`data/` 中的 6 个 JSON 是唯一的内容来源，CSV 为总清单。
- 每个概念包含：要点与评分标准、常见误解、三档追问与提示、复习题、来源编号。
- 前置关系按概念名称引用，并校验不指向教学顺序在后面的概念。

## 已知限制

- 评分逻辑仍在验证，尚未用真实学员的转写做校准。
- 尚未在实体手机上完成完整的端到端通话验收。
- 在线体验页尚未发布。
